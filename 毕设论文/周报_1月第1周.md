### 1. 三层智能体架构实现（约166行核心代码）

基于论文中的"规划-执行"思想，设计了三层分离的智能体协作模式：

#### 1.1 Planner Agent（规划者）
**职责：**
- 接收用户的自然语言指令（如"把音量调到80"）
- 分析意图，识别需要调用的MCP服务器
- 根据关键词匹配找到对应的工具
- 输出**初步计划**（JSON格式），包含服务器名称、工具名称、建议参数

**Prompt设计要点：**
```yaml
role: 意图分析规划者
goal: 理解用户的自然语言指令，分析背后的真实意图
backstory: |
  你是一个专门负责意图理解的智能体。你的任务是：
  1. 分析用户指令中的核心意图（调整音量、修改亮度、应用滤镜等）
  2. 从MCP服务器注册表中找到最匹配的工具
  3. 提取指令中的关键参数（数值、状态等）
  4. 生成结构化的执行计划供后续智能体使用
```

**输出示例：**
```json
{
  "intent": "调整音量",
  "server": "volume_server",
  "tool": "set_volume",
  "parameters": {"level": 80},
  "reasoning": "用户明确要求将音量设置为80"
}
```

#### 1.2 Executor Agent（执行者）
**职责：**
- 接收Planner的输出计划
- 将计划细化为**具体的TODO列表**（分步骤的执行清单）
- 处理可能的依赖关系（如需先查询当前状态）
- 输出**详细的执行步骤**（JSON数组）

**Prompt设计要点：**
```yaml
role: 任务执行规划者
goal: 将高层计划转化为详细的执行步骤
backstory: |
  你是一个负责任务分解的智能体。你需要：
  1. 理解规划者提供的意图和工具选择
  2. 判断是否需要先查询状态（如先get_volume再adjust_volume）
  3. 生成严格的TODO列表，每一步包含工具名称和参数
  4. 确保步骤的逻辑顺序正确
```

**输出示例：**
```json
{
  "todo_list": [
    {
      "step": 1,
      "action": "call_tool",
      "server": "volume_server",
      "tool": "set_volume",
      "args": {"level": 80}
    }
  ]
}
```

#### 1.3 Caller Agent（调用者）
**职责：**
- 接收Executor的TODO列表
- 依次调用MCPManager执行每一步工具调用
- 捕获执行结果和可能的错误
- 生成**执行报告**（包含成功/失败状态、返回值）

**关键实现：**
```python
class VideoAssistantCrew:
    def process_command(self, user_command: str):
        # 1. Planner生成计划
        planning_task = Task(
            description=f"分析用户指令：{user_command}",
            agent=self.planner_agent
        )

        # 2. Executor生成TODO列表
        execution_task = Task(
            description="将计划转化为执行步骤",
            agent=self.executor_agent,
            context=[planning_task]  # 依赖Planner的输出
        )

        # 3. Caller执行工具调用
        calling_task = Task(
            description="执行TODO列表中的所有工具调用",
            agent=self.caller_agent,
            context=[execution_task],  # 依赖Executor的输出
            tools=[self.mcp_manager]  # 注入MCP工具
        )

        # 启动Crew执行
        crew = Crew(
            agents=[self.planner_agent, self.executor_agent, self.caller_agent],
            tasks=[planning_task, execution_task, calling_task],
            process=Process.sequential  # 顺序执行
        )

        result = crew.kickoff()
        return result
```

**经验总结：**
三层架构的核心优势在于**关注点分离**：
- Planner专注意图理解，不关心如何执行
- Executor专注任务分解，不关心意图是什么
- Caller专注工具调用，不关心业务逻辑

这种设计使得每个智能体的Prompt可以更专注、更简洁，降低了LLM的推理难度。同时，三层之间通过**结构化的JSON**传递信息，避免了自然语言的歧义。

### 2. MCP服务器注册表设计（约184行YAML）

设计了统一的服务器配置格式（`mcp_server_registry.yaml`）：

```yaml
servers:
  - name: volume_server
    description: 控制视频流的音量
    command: python
    args:
      - src/mcp_servers/volume_server.py
    capabilities:
      - tool: set_volume
        description: 设置音量到指定级别（0-100）
        keywords:
          - 音量
          - 声音
          - 调整音量
          - 设置音量
      - tool: mute
        description: 静音
        keywords:
          - 静音
          - 关闭声音
          - 关闭音量

  - name: brightness_server
    description: 控制视频流的亮度和对比度
    command: python
    args:
      - src/mcp_servers/brightness_server.py
    capabilities:
      - tool: set_brightness
        description: 设置亮度（0-100）
        keywords:
          - 亮度
          - 调亮
          - 调暗
          - 画面亮度

  - name: video_filter_server
    description: 为视频流应用各种滤镜效果
    command: python
    args:
      - src/mcp_servers/video_filter_server.py
    capabilities:
      - tool: apply_mosaic
        description: 应用马赛克效果（强度1-50）
        keywords:
          - 马赛克
          - 模糊脸部
          - 打码
      - tool: apply_blur
        description: 应用模糊效果（半径1-30）
        keywords:
          - 模糊
          - 柔化
          - 虚化背景
```

**设计要点：**
1. **语义化的关键词**：每个工具配置多个中文同义词，提高匹配准确率
2. **分层结构**：Server层 → Capability层，便于管理和扩展
3. **启动配置**：包含command和args，支持自动启动服务器进程
4. **描述性文档**：每个工具都有详细的description，便于LLM理解

**经验总结：**
注册表是整个系统的**知识库**。通过将工具的语义信息（中文关键词）与技术信息（函数名、参数）分离，实现了"自然语言→工具调用"的语义桥接。这种设计的可扩展性很强：新增工具只需修改YAML，无需改动代码。

## 遇到的问题与解决

### 问题1：CrewAI的Task依赖传递
**现象：**Executor和Caller无法正确获取前置任务的输出
**原因：**CrewAI的`context`参数需要传递Task对象，而不是输出字符串
**解决方案：**
```python
# 错误写法
execution_task = Task(context=[planning_task.output])  # ❌

# 正确写法
execution_task = Task(context=[planning_task])  # ✅
```

### 问题2：MCP Manager的工具注入
**现象：**Caller Agent无法调用MCPManager的方法
**原因：**CrewAI的`tools`参数需要传递符合特定接口的Tool对象
**解决方案：**
将MCPManager包装为CrewAI Tool：
```python
from crewai.tools import BaseTool

class MCPTool(BaseTool):
    def __init__(self, mcp_manager):
        self.manager = mcp_manager

    def _run(self, server: str, tool: str, args: dict):
        return self.manager.call_tool_by_server(server, tool, args)
```

### 问题3：JSON输出格式不稳定
**现象：**LLM有时返回带代码块的JSON（```json ... ```），导致解析失败
**原因：**Prompt中未明确要求"纯JSON输出"
**解决方案：**
在所有期望JSON输出的Task中增加：
```yaml
expected_output: >
  严格的JSON格式，不要包含任何Markdown代码块标记。
  示例：{"key": "value"}
```
